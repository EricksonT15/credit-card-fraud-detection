# Credit Card Fraud Detection

A machine learning capstone project for the Asian Institute of Management (AIM), applying binary classification to detect fraudulent credit card transactions. Built on the ULB Credit Card Fraud dataset, this project covers the full ML lifecycle — problem framing, EDA, feature engineering, SHAP explainability, imbalance handling, model comparison, and bias/fairness auditing.

---

## 📌 Project Overview

| | |
|---|---|
| **Domain** | Finance — Fraud Detection |
| **Task Type** | Binary Classification |
| **Dataset** | [ULB Credit Card Fraud Detection (Kaggle)](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) |
| **Records** | 284,807 transactions (473 fraud after cleaning, 0.167%) |
| **Primary Metrics** | AUC-ROC, F1-Score, Precision-Recall AUC |
| **Author** | Erick |
| **Institution** | Asian Institute of Management |

Despite using a European cardholder dataset, this project is framed with direct relevance to the Philippine digital payments landscape, where the Bangko Sentral ng Pilipinas (BSP) has flagged fraud as a growing systemic risk and no comparable public dataset currently exists.

## ⚙️ Setup Instructions

### 1. Clone the repository

```bash
git clone https://github.com/EricksonT15/credit-card-fraud-detection.git
cd credit-card-fraud-detection
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Download the dataset

This project uses the [ULB Credit Card Fraud dataset](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud), which is too large to be committed to GitHub (~144MB). Download it via the Kaggle API:

```bash
# 1. Get your kaggle.json from kaggle.com → Account → Create New API Token
# 2. Place it at ~/.kaggle/kaggle.json (or /root/.kaggle/kaggle.json in Colab)

kaggle datasets download -d mlg-ulb/creditcardfraud -p data/raw
unzip data/raw/creditcardfraud.zip -d data/raw
```

The notebooks expect the file at: `data/raw/creditcard.csv`

### 4. Run the notebooks in order

```
notebooks/01_data_exploration.ipynb   →  notebooks/02_preprocessing.ipynb
        →  notebooks/03_modelling.ipynb   →  notebooks/04_evaluation.ipynb
```

Each notebook saves its outputs to `data/processed/` so the next notebook can load them without re-running everything from scratch.

## 📊 Key Findings

### Class Imbalance
The dataset is severely imbalanced — after removing 1,081 duplicate rows, only 473 of 283,726 transactions (0.167%) are fraudulent, a 598:1 ratio. Standard accuracy is not a meaningful metric; this project uses AUC-ROC, F1-Score, and Precision-Recall AUC instead.

### Top Fraud-Signal Features
SHAP analysis identified **V14, V12, and V4** as the strongest non-linear fraud predictors — a different ranking than simple Pearson correlation (which favoured V17), demonstrating the value of explainability tools over linear statistics alone.

### Feature Selection
From 32 candidate features, 15 were retained through a three-method consensus (Mutual Information, Random Forest importance, SHAP), reducing dimensionality by 53% while preserving the strongest fraud signal.

### Dimensionality Reduction
t-SNE visualisation revealed four distinct fraud clusters, suggesting fraud is not a single homogeneous pattern but a mix of different fraud typologies — supporting the use of ensemble methods capable of learning multiple decision boundaries.

### Imbalance Handling
Three resampling strategies were prepared and compared: SMOTE (oversampling to 1:1), random undersampling (1:1), and a combined approach (SMOTE to 10% fraud, then undersampling to 1:1) — balancing synthetic data risk against information loss.
